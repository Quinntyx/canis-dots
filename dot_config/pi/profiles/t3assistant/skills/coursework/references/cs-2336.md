# Codio programming handoff

1. Verify the actual course and assignment through Canvas. Follow its linked Codio/external-tool
   launch in the authenticated embedded T3 browser; do not guess a workspace or activity URL.
2. Read instructions, starter materials, required language/version, and grading constraints.
   Identify the active project/activity and any access prerequisite.
3. For browser preparation, leave the relevant activity open for the user. Provide a short
   requirements checklist, relevant course concepts, and a description of the starter layout.
4. The browser handoff leaves activity coding, autograder runs, and submission to the user.
   Separately requested explanations, reference implementations, debugging, or tests use
   [programming assistance](cs-3345.md), keeping reference material distinct from the live activity.
5. Hand off the open tab, verified activity identity, deadline, and remaining human actions. Record
   access/authentication blockers instead of claiming that an LMS workspace is ready.

Preparation opens and verifies the activity before asking the user to take over; an empty
thread is not a browser handoff. Navigation does not authorize platform submission or an
autograder run.
